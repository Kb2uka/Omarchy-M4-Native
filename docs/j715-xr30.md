# J715 native 10-bit graphics

`omarchy-m4-xr30` supplies a private, source-built Mesa runtime for J715
testers using the native XR30 boot framebuffer. It enables the missing
RGB10/X2 render-target and sampling formats. It does not qualify J715 boot,
audio, external displays, or compressed rendering.

## Source and build

The recipe pins GravityLinux/mesa commit
`87ac51d411f0e58a9433567ec2666f457be89e1d` and the archive SHA-256 in
`packaging/omarchy-m4/omarchy-m4-xr30/PKGBUILD`. The tracked
`gpu/j715/xr30/mesa-xr30.patch` contains the format fix and direct compiler
tests; `xr30-probe.c` supplies the separate hardware validation.

The build includes Gallium Asahi, EGL, GBM, GLVND, X11 and Wayland, with
Vulkan and video acceleration disabled. It installs under
`/usr/lib/omarchy-m4/mesa`, leaving both distribution Mesa and `/opt/m4-mesa`
intact. The package materializes library aliases as regular files to retain
the channel's existing archive policy. Compiler prefix maps remove private
build paths.

`tools/build-m4-packages.py` now requires a native aarch64 builder and enables
package `check()` functions. The package workflow uses a native ARM runner.
The XR30 checks run the Asahi compiler suite and the probe's CPU self-test;
build hosts do not run the hardware probe.

The workflow retains makepkg 6.0.2 through a checksum-pinned archive of its
portable scripts. Newer makepkg adds package metadata that would fail the
unchanged published-package identity checks. The checker keeps that
comparison intact; the build does not bump unrelated kernel packages or
ignore metadata differences.

## Delivery

Owners receive the package through `omarchy-m4-update`. The shared command
and setup tool now belong to `omarchy-m4-update` 1-1. On J713, boot package
1-20 transfers those files to the common package in the same transaction and
depends on the XR30 package. The graphics wrapper is inert on J713.

The J715 tester route selects only:

- `omarchy-m4-keyring`
- `omarchy-m4-update`
- `omarchy-m4-xr30`

Enrollment checks the exact board/SoC identity, running tester kernel,
installed tester base package, and inherited manifests. It refuses a J715
with the J713 boot package installed. Before installation, it resolves the
repository-qualified transaction and refuses additional dependencies,
conflicts or replacements. It never invokes the J713 composer or audio/module
helpers. See [updates.md](updates.md) for the shared enrollment command.

A graphics update takes effect at the next graphical login. It does not
restart the desktop or request a boot-object update.

## Session selection and monitor settings

At login, `m4-xr30` selects the private libraries only for J715 with one
connected, native `simple-framebuffer` display whose boot framebuffer format
is exactly `x2r10g10b10`. Missing qualification data, missing runtime files, or
a hold preserves the incoming environment.

Selected sessions retain `ASAHI_MESA_DEBUG=nocompress`, alongside any other
debug flags. The clean candidate failed color-target preparation without
that flag, then passed the same hardware test when the flag matched the live
desktop. Compressed rendering remains unqualified.

The wrapper preserves the owner's monitor configuration. To request 10-bit
output, add `bitdepth = 10` to the existing Lua `hl.monitor({...})` table.
The package does not inject a wildcard rule or replace mode, scale, position,
transform, or other monitor properties. An existing 8-bit choice stays 8-bit.

The loader selection applies to the compositor process and its children,
not the systemd user manager. Existing application wrappers keep their own
renderer choices; Ghostty's software-rendering wrapper is not changed.

## Controls

`m4-xr30 --status` reports selection for the next login, not the format or
libraries used by an already running compositor.

```sh
sudo m4-xr30 --disable
sudo m4-xr30 --enable
```

These commands create or remove `/var/lib/omarchy-m4/xr30/hold`. They do not
change a live session. Enabling removes the hold but does not bypass the
hardware checks.

## Measured limits

On the J715 test system, 2880x1800 at 60 Hz and scale 2, native XRGB2101010
removed the kernel's XRGB8888-to-XRGB2101010 conversion. The clean source
package passed 368 compiler tests and eight full-panel hardware cycles,
covering 32 XR30/XB30 buffer lifecycles, including raw 10-bit pixels, reload,
masked writes, destination-alpha blending and sampled opaque alpha.

The earlier framebuffer traces still put native copy near 21 ms and the
enclosing update near 23 ms. Their damage workloads differ and the parser
has migration-related unmatched entries, so they do not establish a
controlled speedup. The comparison machine has native 120 Hz scanout; this
Air remains on a 60 Hz framebuffer path. Pro-equivalent smoothness is not
established, and recording intervals are not physical display timing.

Validation on October 24, 2026 also passed all 1,499 repository tests, the
12-package policy check against published artifacts, and the signed pacman
sandbox. The sandbox verifies the J713 shared-file ownership migration and
two J715 graphics updates without changing its tester kernel, boot object,
or protected audio/video state. It uses synthetic installed-state fixtures;
it is not a J713 hardware or boot qualification.

The packaged libraries and probe were extracted to a private test directory
for the native J715 GPU run. They were not installed over the live desktop.
The new package's logout/login, repeat-boot and external-display behavior
remain unverified; the earlier live-session evidence belongs to the separate
frozen compositor build.
